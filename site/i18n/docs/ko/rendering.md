# 렌더링의 동작 방식

## 루프

모든 바인딩은 같은 루프를 실행합니다.

```rust,ignore
if chart.needs_redraw() != Invalidation::None {
    chart.build_frame(now_ms, &renderer.measurer()); // &mut chart, ends here
    renderer.render(chart.frame(), &chart.data_view())?; // two shared borrows
}
```

아무것도 바뀌지 않는 동안 `needs_redraw`는 `None`으로 유지되므로, 유휴 상태의
차트는 비용이 들지 않습니다. 프레임 하나를 만드는 데는 데이터 크기와 관계없이 약
20 µs가 걸립니다.

## 프레임

`Frame`에는 배경(그리드), 메인(시리즈, 축), 오버레이(크로스헤어)의 세 레이어가
있으며, 각각 리비전 번호가 붙은 평평한 그리기 명령 목록입니다. 시리즈는
사각형으로 펼쳐지지 않습니다. 프레임은 *이 시리즈를, 표시 범위 i..j로, 이
변환으로 그려라*라고 지시하고, 렌더러는 데이터 열을 직접 읽습니다.

크로스헤어만 움직일 때는 오버레이의 리비전만 바뀌며, GPU 렌더러는 나머지 두
레이어를 캐시한 텍스처를 재사용합니다.

## GPU의 데이터

wgpu 렌더러는 시리즈 데이터를 4096개 봉 단위의 청크로 GPU 버퍼에 보관합니다.
청크는 처음 그려질 때 업로드되고, 그 뒤로는 바뀐 범위만 업로드됩니다. 이동과
확대·축소는 청크당 숫자 몇 개만 바꾸며, 아무것도 다시 업로드하지 않습니다.

가격은 청크마다 기준 가격에 대한 상대값으로 저장되므로, 큰 가격에 작은 틱
단위라도 GPU의 32비트 부동소수점이 정밀도를 온전히 유지합니다.

## 어디서나 같은 픽셀

좌표 계산은 `ferrochart_core::transform_helpers`에 있으며 WGSL 셰이더에 연산
하나하나까지 똑같이 옮겨져 있어서, CPU 렌더러와 GPU 렌더러의 반올림이 동일합니다.
골든 이미지 테스트는 두 렌더러를 같은 기준 이미지와 비교합니다. (미묘한 점이 하나
있습니다. GPU 컴파일러는 `a * b + c`를 반올림이 다른 단일 명령으로 융합할 수
있으므로, 변환은 융합될 수 없는 `(a + b) * c` 형태로 작성되어 있습니다.)
